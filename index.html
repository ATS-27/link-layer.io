Inside the Link Layer

How computers turn raw signals into reliable frames, catch flipped bits when noise corrupts the data, and take turns sharing cables and wireless airwaves.

Author: Atherva Srivastava

Why This Layer Matters: One Hop at a Time

When you open a website, your data doesn't teleport directly to the server. It travels over multiple physical connections: your home Wi-Fi, your cable modem, long fiber optic runs, and router ports.

End-to-End vs. Hop-by-Hop

The Network Layer (Layer 3) plans the global trip from source to destination. But the Data Link Layer (Layer 2) cares about one single hop at a time.

It takes packets from the network layer, packages them into frames, and converts them into physical signals bit-by-bit over the hardware. At the other end, it rebuilds the signals into frames and hands the packet back up.

Simple Analogy: Think of the Network Layer like an itinerary from Mumbai to London (flight, taxi, train). The Data Link Layer is the vehicle carrying you across each individual stretch of road.

The Two Sub-Layers

Logical Link Control (LLC)

The upper half that talks directly to the Network Layer:

  • Protocol multiplexing: Identifies which protocol is inside (IPv4, IPv6, ARP).
  • Flow control: Keeps a fast sender from flooding a slow receiver.
  • Error control: Manages retransmissions if packets get lost.

Media Access Control (MAC)

The lower half that talks directly to the physical hardware:

  • Physical addressing: Uses unique 48-bit MAC addresses burned into network cards.
  • Channel sharing: Decides who gets to speak when multiple devices share a cable or frequency.
  • Frame synchronization: Adds start and stop flags so hardware knows where frames begin.

Functions of the Link Layer

The Data Link Layer carries out six core jobs to make communication reliable across local hardware.

1. Framing

Wraps the incoming network packet in a frame by adding a header (addresses) and trailer (error-checking code).

2. Addressing

Assigns physical Layer-2 hardware addresses (MAC addresses) that uniquely identify each network card on the local link.

3. Synchronization

Sender and receiver agree on clock timing so the receiver knows exactly where bits and frames start.

4. Error Control

Detects bits that flipped due to noise and lets the receiver discard the frame or ask for a retransmission.

5. Flow Control

Slows down a fast sender so it does not overwhelm the receiver's memory buffer.

6. Multi-Access

Sets traffic rules so multiple computers sharing the same wire or Wi-Fi don't speak at once and collide.

When Bits Flip: Three Types of Errors

Electrical interference, heat, and loose wires can distort signals during transit. A 0 can flip to a 1, or a 1 to a 0.

Single-Bit Error

Only one bit in the entire data block flips. It is straightforward to detect with basic parity.

1. Simple Parity Check

The simplest way to check for errors: add one extra bit so the total number of 1s is always even.

How It Works

Say your data is 101010:

  • Count the 1s: there are 3 ones (an odd number).
  • To make the count even, append a parity bit 1.
  • Send: 1010101 (now has 4 ones).
What it catches: Any single flipped bit or odd number of flipped bits.

The Blindspot: If two bits flip at once (e.g. 1010101 turns into 1111101), the count of 1s is still even. The receiver thinks the data is clean and accepts corrupted data!

Rules:

  • 1 Flipped Bit: Exactly 1 row and 1 column parity will fail. Where they cross is the exact bad bit, so you can flip it back and correct it!
  • 2 or 3 Bits: You can detect that an error happened, but you can't be sure which coordinates to fix.
  • 4-Bit Rectangle: If 4 bits arranged in a rectangle flip together, parity checks don't change at all (blindspot).

3. Checksum: Adding Numbers with 1's Complement

Used widely in internet protocols (IP, TCP, UDP). It slices your message into equal chunks, adds them like numbers, and flips every bit to make the checksum.

How Checksum Works

Sender Side:

  1. Divide data into segments (e.g. 8 bits each).
  2. Add the segments together. If there is a carry bit on the end, wrap it around and add it to the total.
  3. Flip all the bits (bitwise NOT) to get the Checksum.
  4. Send the data along with this checksum.

Receiver Side:

  1. Add all received data segments PLUS the checksum together.
  2. Flip all the bits. If the result is all zeros, the frame arrived intact!

4. Cyclic Redundancy Check (CRC): Binary Division

Unlike checksum which uses addition, CRC uses binary division. It is the gold standard used in Ethernet cables and Wi-Fi because it is incredible at catching burst errors.

The 4-Step CRC Recipe

Given data of length n and an agreed divisor (polynomial) of length k:

  1. Step 1: Add (k-1) zeros to the end of the data.
  2. Step 2: Divide using modulo-2 division (XOR instead of subtraction—no borrows!).
  3. Step 3: The leftover remainder (k-1 bits) is the CRC check code.
  4. Step 4: Attach the CRC remainder to the original data and transmit.
Class Example:
Data: 1010000
Divisor (x^3 + 1): 1001 (4 bits, so append 3 zeros)
Divided with XOR to Remainder: 011
Codeword Sent: 1010000011
The receiver divides by 1001. If remainder is 0, the frame is accepted!

Sharing the Wire: Multiple Access Protocols

When multiple computers share a single cable or Wi-Fi channel, they cannot all talk at the same time or their signals smash together. That collision garbles the data. Multiple access protocols are the traffic rules that prevent or handle these collisions.

The Three Families of Protocols

1. Random Access

No device has priority. Any device can transmit when the line looks free. Collisions can happen, so protocols define how to recover.

ALOHA, CSMA, CSMA/CD, CSMA/CA

2. Controlled Access

Devices take turns or ask for permission. Zero collisions occur because only one device is authorized to transmit at any instant.

Reservation, Polling, Token Passing

3. Channelization

The total bandwidth is sliced up among stations by frequency (radio bands), time slots, or unique mathematical codes.

FDMA, TDMA, CDMA

Random Access Deep Dive

Pure ALOHA (Max Efficiency: ~18%)

A station transmits whenever it has data ready. If two stations transmit around the same time, they collide, wait a random back-off time, and try again.

Vulnerable Time: 2*FrameTime. Because transmissions can overlap at any instant, over 80% of bandwidth is wasted in collisions.

Slotted ALOHA (Max Efficiency: ~37%)

Time is divided into slots equal to one frame length. Stations are allowed to transmit only at the beginning of a slot.

Vulnerable Time: Cut in half to 1*FrameTime, which doubles the maximum channel efficiency!

CSMA: "Listen Before You Speak"

Carrier Sense Multiple Access adds a simple habit: check the line first. If it's busy, wait. If it's idle, send.

Why do collisions still happen? Because of propagation delay: electrical signals take time to travel down the physical wire. Station A might start sending, but before its signal reaches Station B, Station B senses an empty wire and starts transmitting too!

CSMA Access Modes

What should a device do when it finds the channel busy?

1-Persistent Mode: The device keeps listening continuously. The very instant the channel goes idle, it transmits immediately. Tradeoff: No idle time wasted, but high risk of collision if multiple stations were waiting for the channel to clear!

CSMA/CD (Collision Detection)

Used in classic wired Ethernet. The network card listens while it transmits.

  • If voltage doubles on the wire, a collision is detected.
  • The station immediately stops transmitting.
  • It sends a quick Jam Signal to alert all devices.
  • Waits a random back-off time before trying again.

CSMA/CA (Collision Avoidance)

Used in Wi-Fi. Radios cannot listen while transmitting because their outgoing signal drowns out reception.

  • Focuses on avoiding collisions before they occur.
  • Waits an Inter-Frame Space (IFS) and counts down a random back-off timer.
  • Can send RTS (Request to Send) and wait for CTS (Clear to Send).
  • Requires an explicit ACK from the receiver to confirm delivery.

Controlled Access (Collision-Free)

Reservation: Stations announce in mini-slots beforehand that they have data, then take turns transmitting in order.
Polling: A primary master station asks each secondary station one-by-one: "Do you have data to send?"
Token Passing: A special token circulates around a logical ring. Only the computer holding the token is allowed to talk.

Channelization (Dividing the Spectrum)

FDMA (Frequency Division): Splits the total bandwidth into separate radio frequency bands. Each station gets its own band.
TDMA (Time Division): Everyone shares the same frequency, but time is sliced into repeating slots. Each station speaks in its slot.
CDMA (Code Division): Everyone transmits at the same time on the same frequency. Each station is assigned a unique code so signals don't interfere.

Case Study: DOCSIS (Data Over Cable TV)

Cable TV companies already had coaxial cables running into millions of homes. In 1997, DOCSIS was created so they could provide high-speed internet through existing TV cables without having to dig up streets.

Because all homes in a neighborhood share the same physical cable, the MAC layer scheduling rules in DOCSIS are essential to keep traffic moving smoothly.

1997 / 1999 DOCSIS 1.0 & 1.1

40 Mbps download / 10 Mbps upload. DOCSIS 1.1 added quality-of-service (QoS) rules to make telephone calls over cable (VoIP) possible.

2002 DOCSIS 2.0

Tripled upload speeds to 30 Mbps by opening up wider upstream bands and using better modulation to resist noise.

2006 DOCSIS 3.0 (Channel Bonding)

Introduced Channel Bonding: combining multiple cable channels together like lanes on a highway. Achieved 340+ Mbps downloads and added IPv6 support.

~2020 DOCSIS 4.0

Supports speeds up to 10 Gbps download and 6 Gbps upload, bringing multi-gigabit speeds to regular coaxial cables.
